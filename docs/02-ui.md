# llamatop — screens (specification for batch 2)

This document fixes **what the dashboard looks like and how it behaves**. The batch 2 task sheets are
written from it, once batch 1 (data) is validated on the real machine.

## 1. Principles

- **Modern**: rounded borders, true-colour palette, gradients on gauges, braille graphs, no ASCII art noise.
- **Dynamic**: every value moves on its own; nothing needs a key press. 1 s data tick, 100 ms animation tick
  (spinner, pulse of the "generating" badge, smooth gauge transitions). Redraw only when something changed.
- **Responsive**: the layout is recomputed on every frame from the terminal size; resizing never crashes,
  never truncates a number in the middle, and degrades in the order given in §3.
- **Legible first**: one accent colour per kind of data, the same everywhere (GPU = violet, CPU = blue,
  memory = teal, server = orange, alerts = red). Colour never carries a piece of information alone: a
  hot temperature also gets a `▲` mark.

## 2. Screens

Tabs, switched with `1`–`5` or `Tab`:

1. **Overview** — everything on one page (default).
2. **Models** — table of all models (state, context, quantization, key settings), details of the selected one.
3. **Logs** — the server log full screen: follow mode, scroll, filter, level filter.
4. **System** — per-core CPU bars, all temperature sensors, disks, network, processes.
5. **Agents** — the OpenCode queue, the followed session, and its timeline of steps (`tasks/T35`). On the
   right, `m` switches between the timeline (the list view) and the activity map (T44).

`?` opens a help overlay listing the keys. `q` or `Ctrl-C` quits and restores the terminal.

### 2.2 Panels

| Panel | Content | Data |
|---|---|---|
| Header | host, uptime, server health dot, build, clock, tabs | `SystemSnapshot`, `LlamaSnapshot` |
| Model | name (short), quantization, state badge (`IDLE`, `GENERATING`, `PROMPT`, `LOADING`, `NO MODEL`, `SERVER DOWN`), live t/s + graph, average prompt t/s, cache reuse, context gauge, draft acceptance, key settings (`ctx-size`, `n-cpu-moe`, `n-gpu-layers`, `threads`) | `LlamaSnapshot` |
| GPU | load gauge, VRAM gauge, temperatures, power, fan, load graph | `GpuSample` |
| CPU | usage gauge, temperature, frequency, load averages, graph | `CpuSample` |
| Memory | RAM and swap gauges, resident memory of the model process | `MemSample`, `ProcSample` |
| Log | last lines, coloured by level, follow indicator | `LogLine` |
| Last request | prompt tokens, generated tokens, speeds, read from the log timing lines | `LogEvent::Timing` |

The map takes up to three-fifths of the panel height (at least `18`, at most `23` rows). The feed shows the
newest steps that fit, oldest on top; each step's duration is right-aligned (`<s>s` below 60 s, `<m>m` below
an hour, `<h>h` otherwise, `0s` when negative). The "now" line names the running station, the running step,
and the time since it started, then the session's tokens, age and step count. The view is drawn only when the
right side is at least `62` columns wide and `30` rows tall (`map::MIN_W + 2`, `map::MIN_H + 12`); otherwise
the Agents screen keeps its list view.

## 3. Responsive rules

| Terminal | Layout |
|---|---|
| ≥ 140 × 40 | 2 columns: Model + Log on the left, GPU / CPU / Memory on the right, graphs shown |
| 100–139 columns | 2 columns, graphs reduced to one line, "Last request" hidden |
| 60–99 columns | Overview is dense (one row per subsystem, then the log); the other screens keep their single-column layout |
| < 60 columns or < 20 rows | compact: one line per subsystem (`GPU 97% 70°C 14.8G │ CPU 38% │ 62 t/s`), then the log |
| < 30 × 8 | a single centred message: "terminal too small" |

A panel that does not have its minimum height is dropped, in this order: Last request, graphs, Memory,
CPU, Log. The Model and GPU panels are the last standing.

On the **Narrow** tier (`60 ≤ w < 100`, `h ≥ 20`) the **Overview** only is dense: the header stays on row 0,
and everything below is drawn frameless — one row per subsystem (model, context, GPU, CPU) separated by thin
rules, then the log, then the keys. When the body is below 12 rows the inner rules drop first, then the
context band. The other screens keep their single-column layout.

## 4. Palette (true colour, dark)

| Role | Colour |
|---|---|
| Background | terminal default (never painted) |
| Border, idle | `#545c7e` (`#3b4261` at first: invisible on a dark terminal background) |
| Border, focused / title | `#7aa2f7` |
| Text | `#c0caf5` — dim `#565f89` |
| Server / model accent | `#ff9e64` |
| GPU accent | `#bb9af7` |
| CPU accent | `#7aa2f7` |
| Memory accent | `#2ac3de` |
| Good | `#9ece6a` |
| Warning | `#e0af68` |
| Critical | `#f7768e` |

Gauges are filled with a gradient from the panel accent to the threshold colour: warning from 75 %,
critical from 90 % (VRAM: 98 / 99.5 %, a loaded model fills it by design; temperatures: GPU junction 85 / 95 °C, CPU 80 / 95 °C). A graph shows a 0 sample as one bottom dot, so an idle graph is visibly alive. Without true colour
(`COLORTERM` unset), the same roles map to the 16 ANSI colours. `NO_COLOR` set: no colour at all, the
`▲` marks and the gauges still read.

## 5. Keys

| Key | Action |
|---|---|
| `1`–`5`, `Tab`, `Shift-Tab` | switch screen |
| `a` | follow the running session (Agents screen) |
| `m` | map / list view (Agents screen) |
| `q`, `Ctrl-C` | quit |
| `?` | help overlay |
| `p` | pause / resume the display (data keeps flowing) |
| `+` / `-` | faster / slower refresh |
| `↑ ↓ PgUp PgDn Home End` | scroll (Logs, Models) |
| `f` | toggle follow mode (Logs) |
| `/` | filter the log (substring, case-insensitive), `Esc` clears |
| `e` | cycle the level filter: all → warnings+errors → errors (Logs) |
| `x` | show / hide the router's proxy lines (Logs; hidden by default: llamatop's own polling makes the router print two per round) |
| `r` | raw / compact log lines (compact by default: no "slot … id N |" prefix) |

## 6. How the screens are checked without eyes

The local model has no visual access. Batch 2 therefore provides:

- `llamatop --demo`: a built-in generator of plausible data (idle → prompt → generating → idle), so every
  state can be shown without a server;
- `llamatop --snapshot 140x40 [--demo-state generating]`: renders **one frame** to standard output as plain
  text (and with `--ansi`, with colours) and exits;
- golden files `tests/snapshots/<screen>-<width>x<height>.txt` rendered through ratatui's `TestBackend`,
  compared in `cargo test`, for at least 140×40, 100×30, 80×24 and 50×15.

The orchestrator reviews the golden files and the `--ansi` output; Florian judges the real thing on the aibox.
